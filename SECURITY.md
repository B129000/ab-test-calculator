## Reporting a vulnerability

**Do not report suspected security vulnerabilities through a public issue, discussion, pull request, commit, or other public channel.**

Security vulnerabilities must be reported using an approved contact method listed on Principal Publisher's GCxchange site:

[Principal Publisher on GCxchange](https://gcxgce.sharepoint.com/teams/10001402/SitePages/Search.aspx)

Access to the GCxchange site may require an authorized Government of Canada account and network access.

When reporting a suspected vulnerability, include the following information when possible:

- A description of the vulnerability;
- The affected page, file, feature, or version;
- The steps required to reproduce the issue;
- The potential impact;
- Relevant browser or operating-system information;
- Screenshots or other supporting evidence that do not expose sensitive information; and
- Any suggested remediation.

Do not include sensitive, personal, protected, or classified information unless requested through an approved secure channel.

## Examples of security issues

Potential security issues may include:

- Cross-site scripting or unsafe HTML injection;
- Manipulation of calculator inputs or outputs in a way that produces misleading results;
- Exposure of personal, protected, or confidential information;
- Inclusion of passwords, access tokens, API keys, or other credentials in the repository;
- Use of a compromised or unapproved external resource;
- Unauthorized modification of the GitHub Pages deployment;
- Dependency or supply-chain risks if external dependencies are introduced; or
- A security weakness in the repository configuration or deployment process.

The calculator does not require an API key, application server, or database. Do not add credentials, production experiment data, personal information, or other sensitive information to the source code, repository history, issues, or pull requests.

## Public issues

Public GitHub issues may be used for ordinary defects, accessibility issues, documentation corrections, and feature requests when they do not disclose a security vulnerability or sensitive information.

If there is uncertainty about whether an issue is security-related, use the approved private reporting channel instead of posting it publicly.

## Response process

After a vulnerability is reported, the project team will assess the report and coordinate the appropriate response through established organizational processes.

Information about a vulnerability should not be publicly disclosed until the project team confirms that disclosure is appropriate.

# Sécurité

## Signalement d'une vulnérabilité

**Ne signalez aucune vulnérabilité de sécurité présumée au moyen d'un problème, d'une discussion, d'une demande de tirage, d'une validation ou d'un autre canal public.**

Les vulnérabilités de sécurité doivent être signalées au moyen d'une méthode de communication approuvée indiquée sur le site GCéchange de l'Éditeur principal :

[Éditeur principal sur GCéchange](https://gcxgce.sharepoint.com/teams/10001402/SitePages/fr/Home.aspx)

L'accès au site GCéchange peut nécessiter un compte autorisé du gouvernement du Canada ainsi qu'un accès au réseau.

Lorsque vous signalez une vulnérabilité présumée, fournissez, dans la mesure du possible, les renseignements suivants :

- Une description de la vulnérabilité;
- La page, le fichier, la fonctionnalité ou la version touchée;
- Les étapes nécessaires pour reproduire le problème;
- Les répercussions possibles;
- Les renseignements pertinents sur le navigateur ou le système d'exploitation;
- Des captures d'écran ou d'autres éléments justificatifs qui ne révèlent aucun renseignement de nature délicate;
- Toute mesure corrective proposée.

N'incluez aucun renseignement de nature délicate, personnel, protégé ou classifié, sauf si ces renseignements sont demandés au moyen d'un canal sécurisé approuvé.

## Exemples de problèmes de sécurité

Les problèmes de sécurité possibles peuvent comprendre :

- L'exécution de scripts intersites ou l'injection de code HTML non sécuritaire;
- La manipulation des données saisies ou des résultats de la calculatrice de manière à produire des résultats trompeurs;
- La divulgation de renseignements personnels, protégés ou confidentiels;
- L'ajout de mots de passe, de jetons d'accès, de clés API ou d'autres identifiants dans le dépôt;
- L'utilisation d'une ressource externe compromise ou non approuvée;
- La modification non autorisée du déploiement GitHub Pages;
- Les risques liés aux dépendances ou à la chaîne d'approvisionnement si des dépendances externes sont ajoutées;
- Une faiblesse de sécurité dans la configuration ou le processus de déploiement du dépôt.

La calculatrice ne nécessite aucune clé API, aucun serveur d'application et aucune base de données. N'ajoutez aucun identifiant, aucune donnée d'expérience de production, aucun renseignement personnel ni aucun autre renseignement de nature délicate au code source, à l'historique du dépôt, aux problèmes ou aux demandes de tirage.

## Problèmes publics

Les problèmes GitHub publics peuvent être utilisés pour signaler des défauts ordinaires, des problèmes d'accessibilité, des corrections à la documentation et des demandes de fonctionnalités, à condition qu'ils ne révèlent aucune vulnérabilité de sécurité ni aucun renseignement de nature délicate.

Si vous ne savez pas si un problème est lié à la sécurité, utilisez le canal privé approuvé au lieu de le publier dans le dépôt public.

## Processus de réponse

Après le signalement d'une vulnérabilité, l'équipe du projet évaluera le rapport et coordonnera l'intervention appropriée conformément aux processus organisationnels établis.

Les renseignements concernant une vulnérabilité ne doivent pas être divulgués publiquement avant que l'équipe du projet confirme que cette divulgation est appropriée.
